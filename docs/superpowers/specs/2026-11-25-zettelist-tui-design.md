# zettelist: TUI (計画 3) の短い設計

状態: 承認済み (2026-11-25)。画面、キー、見た目の方針は本体の設計 `docs/superpowers/specs/2026-11-19-zettelist-design.md` の「機能」「キー操作」「見た目」「入力の方法」に従う。この文書は、計画 3 の範囲と作り方だけを決める。

## 目的

`zl` だけで起動したときの TUI を作る。いまは「TUI はまだありません」と出るだけ (`src/cli.rs` の `Action::Tui`)。利用者は 1 日 1 回ほど、inbox を片付け、提案を確かめるのに使う。

## 範囲

- 入れる: inbox (一覧、全文、似ているノート、30 日超の印、選択、削除)、書く欄 (本文、出典、`ui.locator` のときの位置)、昇格 (題の入力欄と `$EDITOR`)、リンクと Hub のレビュー (`a` `A` `d` `c` `n` `N` `u` `Ctrl-r` `m`)、失敗の一覧、キーの一覧 (`?`)、`[theme]`、`[keys]`
- 入れない: 出典のレビュー (計画 4 の出典の登録と一緒に作る)。Permanent の閲覧 (Studio に任せる)

## 作り方

| 項目 | 選んだもの | 選ばなかったもの |
|---|---|---|
| 画面の状態 | 状態とキーの処理 (`App`) を描画と端末から分け、データの出し入れは trait (`Store`) 越しにする。テストは偽の `Store` と ratatui の `TestBackend` で、端末なしで行う | 状態と描画と omnigraph の呼び出しを 1 か所に書く: 速く書けるが、テストにサーバーと端末が要る |
| CLI と同じ関数 | `src/cli.rs` の中にある書き込み、昇格、マージ、似ているノートの処理を `src/ops.rs` に移し、CLI と TUI の両方から呼ぶ。警告は表示せずに返す (TUI の画面を壊さないため) | TUI 側で同じ処理を書き直す: 2 か所で食い違う |
| inbox の似ているノートの印 | 開いたときに inbox のノートの埋め込みをまとめて読み、カーソルを動かすたびに手元でコサイン類似度を出す。似ている Permanent の上位 3 件はサーバーの `nearest` で引き、ノートごとに覚えておく | カーソルを動かすたびにサーバーに聞く: 1 回に omnigraph の呼び出しが 4 回ほど要り、動きが重くなる |
| Hub の選び直し (`c`) | review ブランチに新しい Hub の提案を書き、元の提案を却下、新しい提案を採用として記録する。`u` で新しい提案を消して元に戻す | 判断ファイルに「Hub の差し替え」という新しい種類を足す: `apply` を変えることになる |

## 見た目

本体の設計のとおり、細部は動く画面ができてから、スクリーンショットを見ながら利用者と決める。計画の最後のタスクのあとに、その場を設ける。

## builder に任せること

- `[theme]` の項目名と既定の色、`[keys]` の書き方 (本体の設計で builder に任せたもの)
- ISBN の書誌検索ページの URL
- 出典の欄の補完を確定するキー
